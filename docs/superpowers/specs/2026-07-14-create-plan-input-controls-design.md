# 创建计划输入控件交互设计

## 目标

让创建计划页中的见面日期、目标到达时间和参与人数上限均可通过点击整块控件直接填写，降低移动端填写成本。

## 交互设计

- 见面日期使用原生 `date` 控件；在 WebKit/Chrome 中，浏览器自身的 picker 命中区域覆盖整块白色输入框，因此点击空白处或日历图标都会打开系统日期选择器。
- 目标到达时间使用原生 `time` 控件；浏览器自身的 picker 命中区域覆盖整块输入框。
- 参与人数上限使用应用内选择面板，仅提供 `2`、`3`、`4`、`5`、`6`，默认值为 `4`；点击展开，选择后立即收起，避免桌面系统原生下拉菜单破坏 H5 视觉一致性。

## 数据与兼容性

- 表单仍提交 `meetingDate`（`YYYY-MM-DD`）、`targetArrivalTime`（`HH:mm`）和 `participantLimit`（数字）。
- 保留服务端及客户端现有的参与人数 2–6 校验，不更改 API、数据库或创建流程。
- 日期和时间继续使用原生浏览器控件，确保 iOS、Android 和桌面端使用各自熟悉的系统选择体验；其关闭时机由平台控制。
- 人数面板使用语义化 `listbox`/`option` 与隐藏表单字段，保留键值提交和现有校验。

## 验证

- 为表单解析增加回归测试，验证 2–6 的人数值会转换为允许的参与人数数字。
- 在浏览器中验证日期和时间整块白色区域可打开原生选择器；验证人数面板可展开、选中后关闭，并可成功提交创建请求。
- 执行项目规定的 lint、test 和 build。
